# Corpus merge — design

**Date:** 2026-09-29 · **Status:** implemented and verified on real data; not yet committed
**Decision log:** D19 (the merge), O8 (Senate share at the break), note on M5

## Goal

One parquet file holding every speech from 2001-01-03 to 2025-12-19, so the
next sampled scoring run and the per-party plots read a single corpus instead
of two. Expected size: 426,718 Stanford + 112,086 govinfo = **538,804 rows**.

## Scope

In:

- a merge step that reads the two processed files and writes one
- renaming the Stanford build output so the merged file can take
  `corpus.parquet`
- a stats file for the merge
- recording the corpus fingerprint in the scoring run manifest (needed because
  the rename changes what `corpus.parquet` means)

Out (each is its own piece of work):

- matching Stanford `speakerid` to bioguide/ICPSR (the DW-NOMINATE crosswalk;
  a rough probe matched 97.4% of Stanford speeches — see the M5 note)
- investigating why the Senate share of speeches drops at the break (O8)
- recording `max_output_tokens` in the manifest (S10 follow-up)
- the 5,200-speech scoring run itself

## Approach

A separate, materialized merge step (approach A), following the pattern of the
two existing builds: logic in `code/src/merge.py`, command line in
`code/scripts/build_merged_corpus.py`, a `make` target, a committed stats JSON.

Rejected:

- **Virtual merge** (a `load_corpus()` helper over both files, no output file):
  no duplicate on disk, but every consumer — starting with `pilot_run.py`,
  which streams from a path — would have to go through the helper, and there
  would be no single corpus file to fingerprint. Contradicts CLAUDE.md's "final
  merged corpus" at a path.
- **One combined build** that re-runs both source builds and concatenates:
  couples them, so a change to either source rebuilds both.
- **Naming the output `corpus_merged.parquet`** and leaving `corpus.parquet` as
  the Stanford build: no renames, but `config.py` already documents
  `CORPUS_PATH` as the merged corpus, and every consumer would need a new
  default.
- **Matching Stanford members to legislators in the same step:** delays the
  merge on validation work the sampled run does not need (it only needs party).

## Files and names

| Artifact | Before | After |
|---|---|---|
| Stanford build output | `data/processed/corpus.parquet` | `data/processed/corpus_stanford.parquet` |
| govinfo build output | `data/processed/corpus_govinfo.parquet` | unchanged |
| Merged corpus | — | `data/processed/corpus.parquet` |
| Stanford stats | `results/metrics/corpus_build_stats.json` | `results/metrics/stanford_build_stats.json` |
| Merged stats | — | `results/metrics/merged_build_stats.json` |

The Stanford stats file is renamed so the three stats files are parallel and
no file called "corpus" stats describes only half the corpus. It is
regenerated by re-running the Stanford build (41 s), not moved, so its
recorded `output_path` is correct.

`config.py`:

- `STANFORD_CORPUS_PATH` (new), `CORPUS_PATH` (unchanged path, now truly merged)
- `BUILD_STATS_PATH` → `STANFORD_BUILD_STATS_PATH`; new `MERGED_BUILD_STATS_PATH`

Make targets:

- `make stanford` — Stanford build (was `make corpus`)
- `make smoke` — Stanford smoke build, unchanged
- `make govinfo`, `make govinfo-smoke` — unchanged
- `make corpus` — the merge; passes `--overwrite`, since re-merging after
  rebuilding either side is the normal workflow and the inputs stay intact

## Schema and row order

`MERGED_SCHEMA` = the 12 corpus columns plus `icpsr` (nullable `int32`) —
identical to `GOVINFO_SCHEMA`.

- Stanford rows get `icpsr = null` until the crosswalk fills it.
- `member_id` stays source-native: Stanford `speakerid` (9 digits, per member
  per Congress), govinfo bioguide id (7 characters). The formats cannot
  collide, and `source` tells them apart. Party-level analysis is unaffected;
  member-level analysis across the break waits for the crosswalk.
- Row order: all Stanford rows (date-sorted, as built), then all govinfo rows
  (in their file order, which is not date-sorted). Nothing downstream depends
  on row order, so no sort — it would need the text in memory.

The merge **never drops a row**: every input row is written, or the build
fails. All filtering belongs to the two source builds, where it is counted.

## Checks

Pass 1 reads only the small columns of both inputs and raises `ValueError` (or
`FileNotFoundError`) naming the problem, before any output exists:

1. Both inputs exist — the message names `make stanford` / `make govinfo`.
2. Schemas match `CORPUS_SCHEMA` (Stanford) and `GOVINFO_SCHEMA` (govinfo)
   exactly — the message names the differing column(s).
3. Each input is a full build: its stats JSON exists, has `limit: null`, and
   its `rows_written` equals the file's row count. Catches a smoke file copied
   into place, and a file rebuilt without its stats being updated.
4. `source` is only `"stanford"` in one file and only `"govinfo"` in the other.
5. Seam: every Stanford date < `SOURCE_BREAK_DATE` ≤ every govinfo date ≤
   `GOVINFO_END_DATE`.
6. `speech_id` is unique across both files together — the message names the
   first few repeats.
7. `party` ⊆ `EXPECTED_PARTIES` (D, R); `chamber` ⊆ {H, S}.
8. Every Congress from the first to the last present has rows (no gap).

The output path must not exist unless `overwrite=True` (`FileExistsError`).

Pass 2 streams both files in 50k-row batches through one writer into a
temporary file next to the output (`corpus.parquet.tmp`), renamed onto the
output only on success. A failure mid-stream deletes the temp file, so a crash
never leaves a half-written `corpus.parquet`.

## Stats: `merged_build_stats.json`

- `output_path`, `built_at`
- `inputs`: per source — processed file path, bytes, SHA-256, row count, and
  the **raw** file's `source_sha256` copied from that source's stats JSON, so
  every merged figure traces back to raw data
- `rows_written`, `rows_by_source`
- `cell_counts`: Congress × source × chamber × party (nested dicts) — the table
  behind the per-party plots, and how the 114th splits between sources
- `year_counts`: year × source × chamber — the discontinuity the methodology
  chapter quotes; this is where the Senate drop shows
- `seam`: last Stanford date, first govinfo date
- `icpsr_missing_by_source`
- `date_min`, `date_max`

## Downstream changes

- `code/src/corpus.py`, `code/scripts/build_corpus.py`: defaults move to the
  Stanford paths; smoke output becomes `corpus_stanford.smoke.parquet`. Module
  docstring updated (it still says the data ends January 2017 and that the
  govinfo loader does not exist).
- `code/scripts/pilot_run.py`: default `--corpus` unchanged (now the merged
  file). The manifest gains `corpus_sha256`: after the rename, the path alone
  no longer identifies the data — the 2026-09-23 manifest says
  `corpus.parquet`, which now names a different file. Docstring row count
  updated.
- `config.py`: sampling comment updated from 32 cells / 3,200 to
  2 × 13 × 2 = 52 cells / 5,200. Smallest cell (119th, R, Senate) holds 1,128
  speeches, so 100 per cell never runs short.
- Docs: CLAUDE.md, README.md and `docs/notes/2026-09-21_stanford_data_reality.md`
  get the new names and targets; the govinfo section's "Not yet merged" is
  replaced. `docs/decisions.md` gains D19, O8 and a dated M5 note, and its
  path references are updated.

## Tests — `code/tests/test_merge.py`

Written before the implementation. Synthetic Stanford and govinfo parquet
files plus their stats JSONs, built in `tmp_path`:

- happy path: row count = sum of inputs; schema = `MERGED_SCHEMA`; `icpsr`
  null on Stanford rows and preserved on govinfo; `text` and `source`
  unchanged; Stanford rows first
- one failing test per check 1–8, asserting the message names the problem
- existing output without `overwrite` raises
- a failure leaves no output and no temp file behind
- stats: cell counts, year counts, seam and provenance match the fixture

## Verification on real data

1. `make stanford` → `stanford_build_stats.json` shows the same counts and raw
   `source_sha256` as the old `corpus_build_stats.json` (426,718 rows).
2. `make corpus` → 538,804 rows; Congresses 107–119; seam 2016-09-09 /
   2016-09-12.
3. `pilot_run.py --dry-run` on the merged file → 52 cells, 5,200 speeches, a
   cost estimate, no API calls.
4. `make test` and `make lint` clean.

Nothing is committed until the result has been reviewed together.
